# LlamaServer Studio improvement roadmap

## Цель

Сделать приложение не просто формой запуска `llama-server`, а удобной Studio для локальных LLM: с понятной структурой, безопасными фоновыми процессами, постоянным статусом сервера, сильным мониторингом и предсказуемым управлением моделями, пресетами и AutoTune.

Документ собран по трем ревью интерфейса и архитектуры. Главный вывод общий: функциональность уже зрелая, но текущая компоновка перегружает левую панель, а `LlamaGUI` содержит слишком много бизнес-логики.

## Принципы

- Сначала стабилизировать UI-потоки, таймеры, логи и метрики, затем двигать крупные блоки интерфейса.
- Каждый перенос логики делать маленькими проверяемыми шагами: core/service модуль, тест, затем подключение в UI.
- Advanced-возможности не прятать навсегда, а группировать по сценариям: Run, Config, Models, Monitor, AutoTune, Integrations.
- Не ломать текущие пресеты, импорт/экспорт CLI и существующие привычные сценарии запуска.

## Этап 0. Safety и база для рефакторинга

Статус: начат.

- Убрать прямой `QApplication.processEvents()` из обработки логов памяти. Выполнено в первом проходе.
- Добавить throttling для обновления Memory Visualization: обновлять пачками или по таймеру, а не на каждую строку лога. Начато: добавлен single-shot flush через `QTimer`.
- Ввести generation-id для metrics poller, чтобы старые сигналы после Stop не оживляли мертвые slots.
- Начать вынос чистой логики из `main.py` в `src/core` и `src/services`.
- Покрывать каждый вынесенный фрагмент unit-тестом.

Начатая правка:

- Markdown-форматирование Runtime Stats вынесено из `LlamaGUI` в `src/core/runtime_stats.py`.
- Memory Visualization больше не обновляется напрямую из каждой пачки логов через `processEvents()`.

## Этап 1. Информационная архитектура

Статус: запланирован.

- Разделить бесконечную левую панель на рабочие зоны: Run, Config, Models, AutoTune.
- Правую часть сделать полезной постоянно: Overview, Monitor, Logs, AutoTune.
- Перенести Runtime Stats из настроек в верхнюю или правую мониторинговую область.
- Пресеты поднять ближе к выбору модели, потому что они управляют всей конфигурацией.
- CLI Preview сделать нижней раскрываемой панелью, доступной из любого сценария.

## Этап 2. Monitor и Runtime Stats

Статус: запланирован.

- Вернуть Memory Visualization как видимую вкладку Monitor.
- Объединить в Monitor память, VRAM/RAM, скорость, токены и активное время.
- Превратить Runtime Stats в KPI-карточки: speed, VRAM, tokens, active time.
- Добавить экспорт статистики из общей модели данных: JSON для машинной обработки, Markdown для буфера/отчета.
- Добавить log search/filter и заметный error banner для критичных строк.

## Этап 3. Запуск и параметры

Статус: запланирован.

- Добавить Preflight Summary перед Start: модель, порт, GPU, context, KV, MTP, ожидаемая VRAM, warning-и.
- Показывать resolved auto values рядом с auto-параметрами: `Auto: 33 layers`, `Auto: Q8/Q8`, `Auto: ctx`.
- Сделать MTP conditional UI: показывать поддержку, но позволять вручную включить параметры для моделей без MTP в названии.
- Для `Restart to apply` показывать diff измененных параметров.
- Добавить inline compatibility warnings рядом с опасными параметрами.

## Этап 4. Model Manager

Статус: запланирован.

- Вынести Local Models и Hugging Face из Launch в отдельную широкую область.
- Сделать searchable model selector.
- Для HF-файлов заменить узкий список на таблицу: имя, quant, размер, part, действие.
- Показать доступное место на диске для папки моделей.
- Улучшить работу с длинными GGUF-именами и несколькими quant-вариантами одной модели.

## Этап 5. AutoTune и Benchmark

Статус: запланирован.

- Вынести AutoTune в широкую вкладку.
- Упростить набор кнопок по состояниям: до запуска, во время запуска, после результата.
- Добавить diff перед `Apply Best`.
- Подсвечивать score/speed/OOM/crash в таблице результатов.
- Подготовить визуальное сравнение baseline и best preset.

## Этап 6. UX polish и единый стиль

Статус: запланирован.

- Ввести единый QSS/design system.
- Унифицировать язык интерфейса.
- Сохранять состояние splitter, вкладок и раскрытых панелей.
- Добавить поиск по настройкам.
- Заменить часть блокирующих `QMessageBox` на уведомления/тосты, оставив модальные окна только для критичных решений.
- Сделать tooltips не единственным местом документации: для сложных расчетов добавить устойчивые info-popup окна.

## Success criteria

- Запуск сервера, импорт/экспорт CLI, пресеты и AutoTune работают без регрессий.
- Лог-поток и мониторинг не вызывают reentrancy через `processEvents()`.
- Основные сценарии видны без километрового скролла.
- Runtime/Memory/Logs доступны как мониторинг, а не как часть формы настроек.
- Крупные изменения имеют тесты на чистую логику и минимально зависят от PySide UI.
